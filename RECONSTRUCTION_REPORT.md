# Reconstruction Report: the "43fu" Ohnahji Timeline UI, with the live-fix fixes ported

Repo: `~/workspace/onjutimeline-target-ui`, branch `metito/target-ui-fixes`.
Base: local clone of `~/workspace/ebv-github/onjutimeline` at `62794f3` (origin URL recorded as `https://github.com/eBV/onjutimeline.git` for documentation only; nothing was fetched from or pushed to any remote, and nothing was deployed).
Goal: reproduce the UI of Vercel deployment `dpl_GJHStc3TJS8Z9zZttiZn68R6r8Bh` (the "43fu" build, 2026-03-26, whose source was never committed) and port the functional fixes from the dashboard live-fix pass (`~/workspace/ebv-github/onjutimeline-dashboard`, branch `metito/live-fix`, see its `FIX_REPORT.md`) onto it, without importing the dashboard design.

## Method

The 43fu bundles are unusually reconstructable: every JSX element in the compiled chunks carries `data-matrix-*` attributes with the original source path, line number, and URL-encoded JSON of its props (including full `className` strings). Reconstruction used the ancestor files at `62794f3` as scaffolding and placed every difference from the chunks' `data-matrix` evidence and literal strings. Reference bundles are kept in `~/workspace/ohnahji-target-ui-ref/`. Confidence is high throughout: bundle evidence is explicit for markup, class strings, data arrays, and logic; where the ancestor already matched the chunk exactly, the ancestor file was kept untouched.

Files verified SHA-identical between the ancestor and the 43fu deployment (kept as-is): `src/index.css`, `src/lib/constants.ts` (pre-fix), `src/hooks/useNFT.ts` (pre-fix), `src/hooks/useSlideScroll.ts` (pre-fix), `src/components/NFTDetailModal.tsx` (pre-fix), `src/components/ErrorBoundary.tsx`, `src/main.tsx`, `src/lib/utils.ts`, `vite.config.ts`, `vercel.json`, `package.json`.

New slide `src/features/lens/SlideLens.tsx` at index 8, background black (the only black slide; chosen as a fresh, brand-consistent canvas, with Lens green `#ABFE2C` used for the badge accent). It queries the public Lens GraphQL API at `https://api.lens.xyz/graphql` with no auth: `posts(request: { filter: { authors: ["0x6582D147eEb571b3B3689C42f4e5416a89F83428"] }, pageSize: TEN })`, spreading `... on Post` for `timestamp` and the metadata union (`TextOnlyMetadata`, `ImageMetadata`, `VideoMetadata`, `AudioMetadata`, `ArticleMetadata`). This exact query was executed live from the sandbox during the build and returned the account's current posts. Posts render newest first as white neo cards with the handle, a relative timestamp, the content as a plain React text node (never `dangerouslySetInnerHTML`; QA proved a fixture post containing literal `<b>` markup renders as text with zero injected elements), image and video and audio elements from the metadata item URLs. Loading, empty and error states are all handled; the error state shows a friendly message with a RETRY button (QA-verified with a 500-intercepted API). React Query caches with a 5 minute staleTime.

### C6. Grove Vault v1 (commit 74b9453)

New slide `src/features/vault/SlideVault.tsx` at index 11, burgundy (maroon family). It reads the connected account via thirdweb's `useActiveAccount` inside the App provider tree and gates on an `eth_call balanceOf` read against the OG contract through the same publicnode RPC pattern as `useStore`. States: not connected (pitch plus a local CONNECT WALLET button), checking, chain-error with retry, connected non-holder ("Hold an OG PFP to enter" plus a MINT AN OG button to `/mint`), and holder (the vault UI, with a held-count badge). The dependency `@lens-chain/storage-client` 1.0.6 was installed and its API taken from the installed typings: `StorageClient.create()`, `uploadFile(file, { acl: walletOnly(address, 1) })` returning `{ uri, storageKey, gatewayUrl }`, `delete(uri, signer)` with `Signer = { signMessage({ message }) }`, adapted from the thirdweb account's `signMessage` when the wallet exposes it; when it does not, the delete button is replaced by a note explaining why. Uploads are capped at the Grove 125 MB limit with a friendly error. The UI carries the required caveat verbatim: "Vault files are public to anyone with the link; only your wallet can edit or delete them." Successful uploads join a session list persisted in `localStorage` (`grove-vault-uploads-v1`, storing uri, gatewayUrl, name, size, uploadedAt, address) with COPY LINK and OPEN actions per item. The slide ships as its own lazy chunk (35.6 KB). No gate contract or shared-folder v2 was attempted, per scope. QA executed the not-connected state; the holder and upload flows require a real wallet signature and a live Grove upload, so they are verified by code and typings only, not executed end to end here.

### C7. Twitch feed on the Live slide (commit 9db48f8)

New serverless function `api/twitch.js` (plain Node handler, no framework). It reads `TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET` from the environment only (no credential is in the code or the repo), obtains an app token via client_credentials with a module-scope cache, and calls Helix `/streams`, `/videos?type=archive`, `/clips` and `/schedule` for broadcaster `907992368`. It returns `{ live, stream, channel, videos, clips, nextStream }` with `Cache-Control: s-maxage=60`, maps thumbnails to 640x360 (percent placeholders are replaced before brace placeholders, a bug the handler test caught), and returns HTTP 200 with `unavailable: true` and empty sections when the env vars are missing, the token request fails, or every Helix call fails. The handler was unit-exercised in Node with mocked fetch: 12 of 12 checks pass, covering the fallback, the live mapping, and the error path. Client side, the Live slide's Twitch tab fetches `/api/twitch` through React Query (60 second staleTime) and renders a LIVE badge with title and viewer count above the existing embed, or an OFFLINE line with the next scheduled stream, plus LATEST BROADCASTS and TOP CLIPS card rows below it; the YouTube tab and both embeds are untouched, and an unavailable response changes nothing visually. QA intercepted `/api/twitch` with a live fixture and verified the badge, viewer count, and both rows; screenshots in `QA/partc-desktop/` and `QA/partc-iphone-*/`. Local QA cannot run the Vercel runtime, so the function was verified as described, not deployed.
